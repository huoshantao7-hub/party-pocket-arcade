# 《云顶快递》制作提示词

下面的提示词可以直接交给编码助手。它描述的是完整可运行游戏，不是介绍游戏的幻灯片，也不把规则机器人伪装成模型。

```text
请创建一个可本地运行的原创横版平台闯关游戏《云顶快递 / Cloud Courier》，借鉴经典超级玛丽式的跑跳手感，但不使用任天堂角色、关卡、贴图、音乐或商标素材。不要做成 PPT 或只有效果图的演示。

技术要求：纯 JavaScript ES Module + Canvas 2D；物理逻辑和渲染分离。画布原生 960×540，固定 120Hz 物理步长，普通桌面浏览器运行流畅。Python 标准库提供本地网页，默认 127.0.0.1:8785。手动游戏和规则演示不依赖模型或第三方在线资源。

美术方向：柔和的奶油白网页、深森林绿控制栏、暖橙色按钮，留白清晰，文字加粗且可读。原创小邮递员、有表情的小怪、圆润浮岛、草地边缘、问号砖、金币、旗帜和终点邮局。场景有远近山丘、云层、太阳或月亮的层次，适度视差和受击/金币粒子。UI 不要使用大段讲解覆盖游戏。

制作三个真正可通关的关卡：晴空邮路、落日汽水厂、星灯云港。每关地图宽度约4400–5200像素，场景随人物横向滚动；难度逐渐增加，包含地面间隙、可从下方穿过的云平台、金币弧线、可顶的问号砖、巡逻小怪、一个中途检查点和终点邮局。确保邮局画面不被地图边界裁掉。

角色初始三颗心。方向键左右移动，空格跳跃，长按跳跃更高，Shift 加速，P 暂停。支持约0.11秒土狼时间和0.13秒跳跃缓冲；固定物理步长防止速度随帧率变化。从上方踩怪得分，侧面碰撞扣血并有短暂无敌；掉坑扣血并从起点/已激活检查点恢复，耗尽心数结束本关。问号砖只能第一次顶出金币，金币不能重复领取。激活检查点恢复三颗心。真实到达终点后显示本关金币、分数与实际用时，按钮进入下一关或重新冒险。

必须明确区分三种模式：
1. 手动闯关：真实键盘和触控输入。
2. 规则机器人演示：显示“规则机器人，非模型推理”，使用普通移动/跳跃输入实际通过物理引擎，不能传送或直接设置分数来冒充通关。
3. Laya 本地模型：连接用户已安装的 NandhaKishorM/laya 模型，真实返回 typed decision；没有模型时清楚报不可用，绝不静默回退到规则机器人。

Laya 接口：GET /api/ai/status；POST /api/ai/load；POST /api/ai/decision {observation,requestId,timeoutMs}；POST /api/ai/cancel {requestId}。输入应是游戏的英文事实观测：人物位置、速度、是否落地、是否可跳、前方地面边缘/峡谷宽度、平台、最近敌人及终点距离；不要偷偷加入规则机器人推荐动作。输出动作只有 left/right/jump_left/jump_right/wait。界面展示真实推理耗时、模型名称、置信度和决策次数，响应标记 measured:true、simulated:false。模型动作按返回结果执行，跳跃按键脉冲若由宿主产生，文档要说明它属于执行节奏，不是模型预测时序。加载可能需要几分钟，提供明确等待状态。

每次最多一个推理请求，忙时返回429，不堆积；模型未就绪503、超时504、取消409、异常500，错误不得带替代动作。暂停、重开、切关、切模式后丢弃迟到响应，不能让旧动作影响新一局。推理失败要暂停并告诉用户没有使用规则机器人替代。真实调用成功不等于证明模型能通关，不编造模型成绩、速度或排行榜。

界面要有三关选择、模式选择、暂停继续、重开、声音开关和全屏。窗口失焦和页面隐藏时暂停，清除按键，不允许粘键。移动端375px竖屏可玩；844×390横屏时，游戏画面和全部触控键必须同屏，可把左右方向放左侧、加速跳跃放右侧，不能只保证没有横向滚动。网页小按钮至少有44 CSS像素的舒适点击区域，支持可见键盘焦点、200%文字放大与减少动态效果偏好。

验证要求：引擎测试覆盖落地/墙碰撞、长短跳、土狼时间、缓冲、顶砖奖励只一次、金币只一次、踩怪/受伤、检查点复活、终点和失败冻结。规则机器人通过正常输入跑完三关并记录实际结果；浏览器独立测试键盘按下松开、触控、暂停重开、切关、模式标识、失焦/隐藏、移动布局和错误提示。真实模型另外做少量本地接口调用并保存非敏感证据，不把规则测试算作模型成功。模型失败案例可以用明确标注的测试夹具，不能伪造实际推理证据。

交付可运行源码、Windows启动入口、README、制作提示词、必要测试和浏览器截图。除非用户另外要求，不发布网站、不创建GitHub仓库、不录制新视频，也不更改已有游戏项目或读取任何凭据。
```
