# 小游戏制作：玩法与手感工作流

给下一款小游戏先写一张简短设计卡，再动代码。具体选择随用户要求调整；以下是检查点，不是固定玩法模板。

## 设计卡

- 玩家是谁、在哪种设备上玩、单局预期多久？单人、同机双人、局域网手柄和真正在线联机要分清。
- 用一句话写目标，并写出“玩家选择 → 游戏响应 → 得失 → 下一次选择”的循环。
- 列出有不同后果的选择，以及胜利、失败、重试和进度机制。回合制还要写明行动顺序、资源消耗、敌人意图或反制窗口。
- 说明关卡或对手如何逐步增加挑战；失败原因应可辨认。参考作品可以借玩法方向，角色、美术、地图和代码保持原创。

先做一段能从开始玩到结算的真实关卡。规则测试证明计分、碰撞、回合和边界正确；是否有趣需要实际试玩观察，不能由测试通过直接推断。

## 操作反馈

给真实事件建立反馈表：例如跳跃、命中、收集、失误、通关分别对应哪些短音效、形变、粒子、数字或轻微镜头运动。按事件重要程度选少量效果；按键应及时响应，反馈应迅速回到静止状态。震动和闪烁要克制，提供减少动态效果的方式。视觉效果不能修改碰撞判定，也不能伪造分数、机器人表现或联网状态。

## 交付检查

- 实际用键盘、鼠标或触控完成核心操作和至少一局；新增平台或设备只声称已验证的范围。
- 复查旧玩法与新增机制的规则测试、服务边界和可恢复的暂停／重开状态。
- 若交付演示视频，录制连续真实游戏运行与画面变化，检查开头、中段、结尾和声音；时长与字幕遵循当次用户要求。
- README 写明启动方式、玩法模式、已验证范围及实验功能；制作提示词须与实际源码一致。
